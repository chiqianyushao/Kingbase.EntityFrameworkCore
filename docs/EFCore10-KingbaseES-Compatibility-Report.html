EF Core 10 - KingbaseES Provider 全语法兼容性分析报告

  • 报告日期：2026-08-04
  • EF Core 基线：10.0.9
  • Provider：Kingbase.EntityFrameworkCore 10.0.0-alpha.3
  • ADO.NET 驱动：Kdbndp_V9 10.0.1.703（net10.0）
  • 实测数据库：KingbaseES V009R001C002B0014，database_mode=oracle
  • 隔离测试库：efcore10_kingbase_dev

最终结论：当前仍不能宣称 EF Core 10 所有语法均支持，但本轮已清空现有单节点环境中可补齐的主要“未验证”项。 当前版本通过 58 项 Release 回归，其中 34 项为真实 Kdbndp 集成测试；新增验证关系型 complex type、空/大参数集合、微秒/纳秒/DayNumber、null 补偿、Enum、内联 byte[]、JSON 文档、int[]/List、range、全文函数、DataSource/单主机 MultiHost、通知跟踪、Seeding、Interceptor、Index INCLUDE 和 NativeAOT。剩余缺口均在下文标明具体限制。

1. 状态定义

标记 含义
✅ 已验证 已在真实 KingbaseES + Kdbndp 上执行并通过，或纯 EF Core 客户端行为与数据库无关且已有测试
🟡 基础支持 EF Core 关系型默认实现能够处理，当前 Provider 没有专用实现；只适合简单场景，未完成完整规范测试
🟠 部分支持 一部分语法可用，但复杂形态、数据库语义或边界条件不完整
❌ 不支持 当前缺少类型映射、SQL 翻译、服务注册或数据库实现，调用会失败或不能保证语义
⛔ EF 无服务端语义 EF Core 10 关系型查询管线没有该 Queryable 操作的服务端翻译入口；不能由 Kingbase SQL 方言层单独补齐，若强制支持需要修改/分叉 EF Core 查询核心
🚫 不适用 其他数据库 Provider 的专有功能，不属于 KingbaseES 公共 EF Core 兼容范围

“EF 无服务端语义”并不是说该 LINQ 方法在 .NET 中不能使用，而是说：方法只能在 IEnumerable/AsEnumerable() 之后由 .NET 客户端执行，EF Core 10 不会把它转换为数据库 SQL。例如任意 accumulator 的 Aggregate、按固定大小返回嵌套集合的 Chunk、依赖两个有序序列逐项配对的 Zip，都没有通用且语义等价的关系型 SQL 表达。数据库 Provider 只能实现 EF Core 已交给 Provider 的 SQL 方言部分；若要让这些方法保持原始 IQueryable 用法并在服务器执行，需要修改 EF Core 查询核心、定义排序/空值/重复值语义并新增 SQL 树节点，不能通过增加一个 Kingbase 函数翻译器完成。

2. 审计依据

  1. EF Core 10.0.9 官方程序集反射：Queryable、EntityFrameworkQueryableExtensions、RelationalQueryableExtensions、RelationalDatabaseFacadeExtensions、全部公开 MigrationOperation。报告逐项列出公开方法名和重载数量；同名重载共享一条兼容性结论，不重复展开每个泛型参数签名。
  2. EF Core 官方源码标签 v10.0.9，提交 6fecf7f6e78403c04ce8e127a0606336109d690c。
  3. Entity Framework 官方文档仓库，审计提交 7ca120dcb01fa940686da9d3b9c8dd381a93e520。
  4. 仓库 V9R1C10 金仓官方 PDF 文档。
  5. 当前 Provider 源码和真实数据库 Release 回归：51 个测试全部通过，其中 27 个为 Kdbndp 真实库集成测试。
  6. 自动 API 契约测试反射锁定 .NET 10 的 63 个 Queryable 方法名称、EF Core 10 的 39 个 EntityFrameworkQueryableExtensions 名称和 6 个 RelationalQueryableExtensions 名称；新增或遗漏 API 会直接导致测试失败。

16. 当前最明确的不支持清单

  1. EF JSON 聚合模型：complex/owned JSON、任意 JSON path、partial update 与 JSON ExecuteUpdate 需要 EF JSON SQL tree、materializer 和 update pipeline。
  2. Stored procedure CUD/SaveChanges：需要修改命令批次生成，并处理结果列和并发返回值。
  3. HiLo：需要 Kingbase sequence HiLo value-generator factory、注解和模型约定；普通 sequence 支持不等于 HiLo。
  4. 统一 rowversion：Kingbase Oracle 模式没有 SQL Server rowversion 等价类型；当前仅支持普通 concurrency token。
  5. Spatial/NetTopologySuite：当前实例未安装空间扩展，postgis_version() 不存在。
  6. NodaTime：需要 NodaTime 包及 Kdbndp 对应插件/转换器，应作为独立扩展包。
  7. 窗口函数 API：数据库支持窗口 SQL，但 EF Core 10 无通用公开表达式入口。
  8. Queryable 无服务端语义项：Aggregate/AggregateBy/Append/Chunk/CountBy/DistinctBy/ExceptBy/Index/IntersectBy/MaxBy/MinBy/Prepend/SequenceEqual/Shuffle/SkipLast/SkipWhile/TakeLast/TakeWhile/UnionBy/Zip 没有 EF Core 10 关系型翻译入口；不采用隐式客户端回退。
  9. 数据库限制：AlterDatabaseOperation 在线修改现有数据库 collation 不受支持。
  10. 环境拓扑限制：单节点不能验证真实主备切换、网络分区和拓扑健康检查。
  11. 尚需扩大验证：官方 relational specification tests、Oracle/pg 双模式 CI、Database First 高级对象和大规模压力测试。
